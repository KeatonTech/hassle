An automation condition builder (`StateExpr`) was passed to a dashboard `visibility=`/conditional-card slot at test_dashboard_errors.py:<line>, which needs a Lovelace condition. Lovelace conditions are a different schema from automation conditions -- `entity`/`state`/`state_not` keys instead of `entity_id`/`condition` shapes, plus the UI-only `screen` and `user` kinds -- so HA would store this one and then never evaluate it. Fix: use the `cond` vocabulary instead (`from hassle.cards import cond`), e.g. `cond.state(entity, "on")` -- or pass a verbatim `dict` for a condition kind Hassle does not model yet.
