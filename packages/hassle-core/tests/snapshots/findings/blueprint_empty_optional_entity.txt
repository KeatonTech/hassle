The blueprint input `lights_pause_boolean` is an optional entity selector defaulting to `""`, and `blueprints/automation/local/bad.yaml` uses it as a literal `entity_id:`. Home Assistant validates the STATIC expanded configuration, so it rejects the empty entity id with an opaque HTTP 400 at save time -- even when a runtime condition means that branch could never execute with the input empty. Fix: bind the input to a run variable and use a TEMPLATED target instead of a literal one: add `- variables: {lights_pause_boolean: !input lights_pause_boolean}` at the top of `actions:`, then write `entity_id: "{{ lights_pause_boolean }}"`. A template defers the check to runtime, where your existing guard means it never renders empty. See docs/internals/blueprints-design.md §6.3 for the worked example.
